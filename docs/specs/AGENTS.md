Spec documents are source of product/design intent and requirements for big new features or changes. They include information like:

- goals
- non-goals
- architecture
- behavior
- UI/UX logic

### Spec Lifecycle

At the top of spec docs put lifecycle metadata:

```
**Status:** Done
**Accepted:** 2026-08-03
**Implemented by:** #101, #102, #103
**Supersedes:** None
```

**Status** Draft → Accepted → In Progress → Done → Superseded

### How to Write

We do not need to use normative language. These are not contracts. They capture high level thinking and design in a way to make it clear and understandable.
